# Страница tools в корне проекта

**Из todo.md:** страница tools в корне проекта с ссылками на инструменты и описанием, что и зачем.

## Цель
Одна страница `tools.html` рядом с `index.html`. На ней все стенды и отладочные средства: ссылка,
описание, когда пригодится, полезные URL-параметры.

## Что есть сейчас
- Стенды в `src/debug/`:
  - `map-viewer.html` — карта мира: острова, глубины, берег, растительность. Параметры `map, layers, veg,
    tstep, cam, bench, autoregions`;
  - `props-viewer.html` — библиотека объектов: флора и постройки. Параметры `obj, cat, style, cam, views`;
  - `boat-viewer.html` — модель лодки и сценарии анимации моряка. Параметры `views, cam, live, status,
    seat`;
  - `sailor-viewer.html` — модель моряка. Параметры `yaw, pitch, blink, views=turn|hero, t`.
- Скрипты для jsc:
  - `src/debug/run-polar.mjs` — поляра без браузера;
  - `src/debug/trace.mjs` — трасса физики (tws=7, twa=60), без поясняющего заголовка.
- Параметры игры (`src/main.js:35-205`): `map, pos, veg, dpr, perf, touch, auto, t, twa, wind, winddir,
  cam, camaz, campolar, camdist, campitch, reefs, board, tod, clouds, log`.
- Консоль: `window.__sim` (`main.js:269`), `polar(10)`, `runCase({...})`.
- Упоминания разбросаны по `README.md` (разделы «Отладка физики», «Производительность», «Структура»).

## Черновой план
1. `tools.html` в корне, статичная страница:
   - **Стенды** — карточки: название, 1–2 предложения «что и зачем», ссылка, примеры ссылок с
     параметрами (например `map-viewer.html?map=demo&layers=depth`);
   - **Игра с параметрами** — готовые ссылки: `?perf=1`, `?touch=1`, `?t=30&twa=60&cam=chase`,
     `?map=archipelago`, `?tod=0.9`, `?clouds=…`, плюс таблица всех параметров;
   - **Консоль** — `__sim`, `polar()`, `runCase()`;
   - **CLI** — команды jsc и запуск сервера.
2. Стиль — токены из `style.css` (подключить его же или вынести переменные), лёгкая сетка карточек,
   нормальный вид на телефоне.
3. Ссылки на страницу: из `README.md` (раздел «Отладка»), опционально — из справки в игре.
4. Добавить поясняющий заголовок в `trace.mjs`.
5. Чтобы список параметров не устаревал: правило «добавил параметр в `main.js` — допиши в tools.html»
   (упомянуть в README). Генерировать таблицу из общего реестра — отдельный рефакторинг, вопрос 2.

## Затрагиваемые файлы
Новый `tools.html`, `README.md`, `src/debug/trace.mjs` (комментарий). Опционально: `index.html`
(ссылка в справке).

## Риски и ограничения
Страница устаревает вручную. Точки входа стендов лежат в `src/debug/`, пути относительные — проверить
работу из корня под `python3 -m http.server`.

## Вопросы к пользователю
1. Ссылка на tools из самой игры (в справке / меню паузы) или только по адресу `/tools.html`? *По
   умолчанию: маленькая ссылка внизу справки.*
2. Список параметров вести вручную в tools.html или вынести реестр URL-параметров в отдельный модуль
   (`src/params.js` с описаниями), чтобы из него строились и разбор в main.js, и таблица на странице?
   *По умолчанию: вручную сейчас, реестр — потом.*
3. Нужны ли превью-скриншоты стендов на карточках (картинки в `docs/` или `tools/img/`)? *По умолчанию:
   нет.*
4. Язык страницы — русский, как README? *По умолчанию: да.*

## Как проверить
Под `python3 -m http.server` открыть `/tools.html`, пройти по всем ссылкам: каждая открывает
стенд или игру с нужным состоянием. Скриншот на ширине 390 px — без горизонтальной прокрутки.
