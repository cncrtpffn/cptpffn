# Аудит производительности «Кэтбот» и план оптимизаций

## Контекст
Кода стало много (~5.7k строк), нужен аудит производительности: где тратится кадр и что чинить в первую очередь.
Цель — запас по кадру на телефонах (там GPU в 5–8 раз слабее, чем на M4) без потери картинки на десктопе.

## Как мерили
Headless Chrome (Apple M4, ANGLE/Metal), окно 1200×678, DPR 2 (буфер 2400×1356), облака «Кучевые», ветер 6 м/с.
Через initScript подменяли `drawElements*` (draw call'ы и треугольники) и `requestAnimationFrame` (CPU кадра), GPU-время —
через `EXT_disjoint_timer_query_webgl2`. Части сцены выключали по одной через `window.__sim`, шейдер воды патчили на лету.

### Цифры
| Метрика | Значение |
|---|---|
| GPU кадра | **~9.8 мс** (из них пустая сцена с MSAA при DPR 2 — 2.1 мс) |
| CPU кадра (JS + отправка в three) | 2.6 мс; вся симуляция (физика, волны, брызги, след) — **0.15 мс** |
| Draw call'ов / кадр | **378** (лодка — 358 из них) |
| Треугольников / кадр | 330k |

Что сколько стоит:
| Что | GPU | Draw call'ы | CPU |
|---|---|---|---|
| Ближняя вода (фрагментный шейдер) | **~5 мс** (стандартный PBR ≈1.8, свои эффекты ≈3.4, из них след ≈0.8) | 1 | — |
| Плоское отражение | ~0 на M4 | +123 | +1.1 мс |
| Карта теней (2048², PCFSoft) | ~0.3 мс | +110 | — |
| Лодка + моряк + такелаж (127 мешей) | ~0 | 358 (×3 прохода) | ~0.8 мс |
| Облака, острова, небо, частицы | <0.3 мс каждое | мало | — |

Вывод: **по GPU узкое место — шейдер воды и разрешение буфера (DPR 2 + MSAA), по CPU — число draw call'ов от лодки,
умноженное на три прохода (основной, тени, отражение)**. Физика и частицы дешёвые, их не трогаем.

## Проблемные места (по приоритету)

### P1. Шейдер воды — половина GPU-кадра
- `src/scene/water-fx.js:67-95` `wakeFoam`: на каждый пиксель в радиусе 80 м идёт цикл до 39 сегментов. Это самый дорогой
  отдельный эффект (~0.8 мс). Исправление: считать в JS AABB точек следа (+ запас на ширину усов), передавать `uWakeBox`
  и выходить сразу, если пиксель вне коробки (вместо проверки круга в 80 м). В цикле — дешёвая проверка по расстоянию
  до сегмента до тяжёлой математики.
- `src/scene/water.js:111-143`: остальное размазано (рябь 4 октавы `vnoised` + `fwidth`, 5 `vnoise` на барашки и полосы,
  2 на оттенок, блики, `skyColor` в отражении), каждое по 0.1–0.35 мс, а вместе ≈2.6 мс. Исправление: LOD по расстоянию —
  дальше ~120 м не считать рябь и мелкий шум пены (там они всё равно гасятся `fpx`), объединить `hash12` у соседних октав.
  Перед правками — сравнить скриншоты до/после.

### P1. Разрешение буфера
- `src/main.js:31-32`: `antialias: true` + `setPixelRatio(min(dpr, 2))`. Пустая сцена — уже 2.1 мс, а вода масштабируется
  с числом пикселей. Исправление: на таче DPR не больше 1.5; на десктопе — динамическое разрешение: если медиана
  GPU/кадра выше бюджета, шаг DPR вниз (2 → 1.5 → 1.25), есть запас — вверх. Ползунок/авто в панели «Погода и сцена».

### P2. Draw call'ы лодки ×3 прохода
- `src/scene/boat-mesh.js:358` `add()` ставит `castShadow/receiveShadow` всем 127 мешам; `src/scene/sailor.js:125` — то же.
- Неподвижные части корпуса (`boat-mesh.js:362-436`: корпус, палуба, кокпит, пиллерсы, бруски) собрать по материалам
  в один меш на материал — тем же приёмом, что уже есть в `createFittings` (`src/scene/boat-fittings.js:16-26`,
  `mergeGeometries`). Вынести бакеты в общий хелпер и переиспользовать.
- Такелаж (`src/scene/boat-rigging.js`): 24 бокса риф-сезней (`:199`) → один `InstancedMesh`; 8 сегарсов (`:205`) и
  6 сезней (`:210`) → `InstancedMesh`; статичные блоки и детали гика внутри `rig` слить в один меш.
- Мелочь (пуговицы, глаза, блоки, сегарсы, сезни, кронштейны руля) — `castShadow = false`: в тени 2048² на 56 м их не видно.
- Ожидаемо: 378 → ~120–150 draw call'ов, −1 мс CPU на M4 (на телефоне в разы больше).

### P2. Плоское отражение рендерит всю сцену
- `src/scene/planar-reflection.js:58-73` + `src/main.js:221`: второй полный рендер (+123 call'а, +1.1 мс CPU). Исправление:
  отдельный слой `three.Layers` для отражения — корпус, парус, мачта, острова (без травы и мелких деталей); зеркальная
  камера рендерит только его. Заодно убрать аллокации на каждый кадр (массив `hide` в main.js, `vis` в planar-reflection.js).

### P3. Тени
- `src/scene/environment.js:44`: 2048² PCFSoft каждый кадр. После P2 call'ов станет меньше сами собой. На таче — 1024 и
  `PCFShadowMap`.

### P3. Мусор для GC каждый кадр (мелкие паузы на телефонах)
- `src/physics/waves.js:169` `heightAt` создаёт объект `o` на каждый вызов — это тысячи вызовов в кадр (5 на шаг физики × 120 Гц,
  проверка капель в `particles.js:111`, 160 в `shore-spray.js:104`, буи). Нужен один переиспользуемый скретч-объект.
- `src/physics/wind.js:39` `vector()` и `:58` `apparent()` возвращают новые объекты, вызываются на каждом шаге и из каждого
  эмиттера. `src/physics/boat.js:24,35,297` — `foilForces` и `this.forces` тоже аллоцируют на каждом шаге.
- `src/scene/camera.js:55-70`: 2–4 `new Vector3` за кадр.
- `src/scene/wake.js:19,24`: `unshift` + `forEach` с замыканием → кольцевой буфер.

### P3. HUD пишет в DOM каждый кадр
- `src/ui/hud.js:47-104`: ~20 `textContent`/`style`/`setAttribute` на кадр без проверки на изменение, `innerHTML` для
  предупреждений каждые 3 кадра, даже если текст тот же. Исправление: кэшировать прошлое значение и писать только при
  изменении (хелпер `set(el, key, value)`), текст обновлять ~10 Гц, стрелки розы — каждый кадр.

### P3. Облака
- `src/scene/clouds.js:339-357`: каждый кадр переписываются и целиком отправляются все 900×16 float матриц (57 КБ),
  хотя живых 328. Нужно `addUpdateRange(0, count*16)`, как уже сделано в `particles.js:94-98`.

### Не трогаем (проверено, дёшево)
Физика лодки и волн (0.03 мс), частицы (≤0.01 мс в шторм на M4), берег/прибой (0.03 мс), вершинный шейдер воды
(31k вершин × 16 гармоник), запекание карты берега (только при старте).

## Порядок работ
1. `docs/changes/perf-audit/plan.md` — этот аудит с цифрами (по конвенции); в конце — `summary.md` с цифрами до/после.
2. Замерочный режим `?perf=1`: оверлей с GPU-мс (timer query), CPU-мс, draw call'ами и треугольниками (`renderer.info`).
   Он нужен для приёмки каждой следующей правки.
3. P1: динамический DPR + DPR на таче, раннее отсечение следа, LOD шейдера воды.
4. P2: слияние статики лодки, инстансинг такелажа, `castShadow` на мелочи, слой отражения.
5. P3: аллокации, HUD, облака, тени на таче.

## Проверка
- `python3 -m http.server` (вне песочницы), headless Chrome через chrome-devtools MCP; тот же сценарий
  (`?clouds=Кучевые`, плюс шторм `?wind=16`, плюс вид с палубы `?cam=deck`), сравнить GPU/CPU/draw call'ы с таблицей выше.
- Скриншоты до/после с одинаковыми `?t=…&cam=…&camaz=…` — картинка воды, лодки и отражения не должна заметно поменяться.
- `?touch=1` — проверить мобильный профиль (DPR, тени, отражение выключено).
- Физику не трогаем, поэтому прогон `?t=30&auto=1&log` должен давать те же числа, что до правок.
