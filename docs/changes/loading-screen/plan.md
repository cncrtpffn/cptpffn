# 01 — Экран загрузки с этапами и компасом-троббером

## Контекст
Сейчас при старте висит статичный `<div id="loading">Загрузка…</div>`, весь запуск `main.js` — один
синхронный блок, текст этапа не перерисовать. Задача из `docs/backlog/01-loading-screen.md` + ответы:
- минимальный экран в стиле HUD демки (шрифт Nunito, `--card`, `--ink`, фон `#9fd3ec`);
- троббер — большой компас из HUD: картушка, истинный и вымпельный ветер, гик; петля 3 с, сценарий
  **«полный круг»**: лодка разворачивается на 360°, истинный ветер гуляет ±15°, в цикле оверштаг и
  фордевинд, гик ведёт себя как в физике; значения посчитаны заранее;
- тайминги этапов — всем, мелким серым;
- кнопки «Начать» нет (появится со звуком);
- статичная страница в том же дизайне видна сразу, ещё до загрузки модулей с CDN.

Документы задачи: `docs/changes/loading-screen/plan.md` (копия этого плана) + `summary.md` по шагам.

## Ключевое решение: анимация на CSS, на потоке композитора
Пока идут тяжёлые синхронные шаги (`buildWorld`, запекание берега, компиляция), JS-анимация на rAF
стоит. Поэтому компас крутим **CSS-анимацией `transform`**, а не через JS. Каждый подвижный слой
(картушка, истинная стрелка, вымпельная стрелка, гик) — отдельный `<svg>` того же viewBox, положенный
поверх остальных (`position:absolute`, `will-change: transform`). Анимации `transform` на таких
элементах браузер ведёт в композиторе, и при занятом главном потоке они продолжают идти. Анимация
внутренних элементов SVG так не умеет. Гик вращается вокруг мачты (`transform-origin` в точке мачты).
Тот же CSS работает и на статичной странице до запуска JS.

## Шаги

### 1. Генератор кадров анимации (jsc)
Новый `src/debug/gen-loading-anim.mjs`, запуск `jsc -m src/debug/gen-loading-anim.mjs > src/ui/loading-anim.css`:
- скорость лодки по TWA — из `runCase` (`src/debug/polar.js`) при tws 7 (как в `start.json`), таблица
  через 15° с интерполяцией;
- курс ψ(t) = −360°·t/3 с, ветер `dir(t) = 15°·sin(2πt/3)`, оба периодичны;
- `awa/aws` — та же формула, что `Wind.apparent` (`src/physics/wind.js:49`);
- гик — настоящий `Sail.update` (`src/physics/sail.js:66`): шкот на автотриме (`|awa| − 24°`, как
  автопилот в `main.js:263`), шаг 1/120 с, два цикла на разгон, чтобы состояние замкнулось; пишется
  третий цикл. Тогда задержка by-the-lee 15° и быстрый перелёт при фордевинде будут как в игре;
- вывод: 4 блока `@keyframes` (card, true, app, boom), 60 ключей (шаг 50 мс), углы без перескоков
  через ±180°; заголовок «сгенерировано, не править руками».

### 2. Разметка и стиль (статичная страница)
- `index.html`: `#loading` → карточка `.panel`-стиля по центру: стек слоёв компаса 220 px (обод,
  риски/буквы/цифры как в `Hud` — сгенерированы тем же скриптом в разметку или статичным SVG;
  силуэт лодки, мачта, гик, стрелки), заголовок «Кэтбот», полоса прогресса (`.bar`/`.fill` из HUD),
  строка этапа (стартовый текст «Загрузка модулей…»), под ней `<ol>` завершённых этапов с мс
  (`--ink-soft`, 11 px).
- `<link rel="stylesheet" href="src/ui/loading-anim.css">` в `<head>`.
- `style.css`: блок `#loading` заменить, классы компаса переиспользовать (`.rose-ring`, `.arrow-*`,
  `.rose-boom`, `.rose-boat`, `.lubber`). Телефон: компас 150 px, как у HUD. Плавное скрытие —
  `opacity` 0.4 с, затем `remove()`.
- `diag.js` `showFatal` уже пишет в `#loading` через `replaceChildren` — экран ошибки остаётся рабочим;
  проверить вид, при необходимости остановить анимацию классом `.diag-fatal`.

### 3. Модуль `src/ui/loading.js`
- `step(label, weight)` — закрыть предыдущий этап (мс в список), показать новый, полоса = сумма весов
  закрытых / общая сумма;
- `await frame()` — отдать кадр: `requestAnimationFrame` + `setTimeout 0`, чтобы текст отрисовался;
- `done()` — закрыть последний этап, таблица таймингов в консоль (`console.table`) и в `diag.info`,
  плавное скрытие.
Веса — по типичным мс из `world.summary()` / `bakeMs` на десктопе (замерю на шаге 4).

### 4. `main.js` и `world.js`: этапы с отдачей кадра
- `world.js`: тело `buildWorld` → генератор `*worldSteps(map, opts)`, который отдаёт имя каждого
  `lap()`. Синхронная `buildWorld` прогоняет его до конца (стенд карты и Архипелаг без изменений,
  результат тот же), новая `buildWorldAsync(map, opts, onStep)` ждёт `await onStep(name)` между
  шагами.
- `critical()` синхронный — добавить рядом `criticalAsync` в `src/diag/features.js` (тот же
  try/catch, `await create()`), не трогая остальных вызовов.
- Этапы в `main.js`: «Настройки» (start.json) → «Рендерер» → «Мир: поле высот / биомы / план /
  рельеф / поселения / растительность» → «Небо и свет» → «Карта берега» → «Вода и кильватер» →
  «Лодка и брызги» → «Интерфейс» → [«Промотка ?t=»] → «Шейдеры» (`compileAndCheck`) →
  «Первый кадр» (прогревочный `planar.render` + `renderer.render` под заставкой, убирает фриз
  первого кадра) → `loading.done()` → `diag.started()` → rAF. Между этапами `await loading.frame()`.
- Сводка `world.summary()` и строка `[shore]` остаются в консоли как есть.

## Проверка
- Сервер: `python3 -m http.server` вне песочницы, Chrome DevTools MCP (одна вкладка).
- Анимация: скриншоты/скринкаст 3 с петли; проверить, что гик на правильном борту
  (ветер справа → гик слева), на оверштаге проходит ДП, на фордевинде перелетает с задержкой.
- Композитор: performance-трейс старта — компас крутится во время `buildWorld`/запекания (кадры
  композитора идут при длинной задаче главного потока). Отдельно проверить в Safari; если там
  анимация встанет, это будет видно только как пауза на долгих этапах — записать в ограничения.
- Этапы меняются, полоса растёт; сумма мс мира совпадает с `world.summary()`, «Карта берега» — с `bakeMs`.
- Нет фриза после скрытия: `?perf=1`, первые кадры без пика CPU (трейс).
- `?touch=1` — вид на телефонной ширине; `?fail=world:init` — экран «Игра не запустилась» на месте
  заставки; статичная страница (троттлинг сети в DevTools) — компас крутится до запуска `main.js`.
- Стенд карты `src/debug/map-viewer.html` открывается как раньше; `jsc -m src/debug/run-polar.mjs`
  — вывод не изменился.
