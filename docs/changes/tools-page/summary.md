# Страница tools и реестр URL-параметров — итог

План: [plan.md](plan.md). Пункт беклога: [03-tools-page.md](../../backlog/03-tools-page.md).

## Что сделано

### Реестр `src/params.js`
- `GAME_PARAMS` — 21 параметр игры: `name`, `kind` (num | flag | str | list), `group`, `desc`, `example`,
  необязательные `values` и `default`. `PARAM_GROUPS` задаёт порядок групп: «Карта и старт», «Ветер и лодка»,
  «Камера», «Сцена», «Отладка».
- `readParams(search = location.search)` возвращает только заданные параметры реестра, уже приведённые к типу:
  `{ wind: 9, perf: true, pos: [160, -90, 180] }`. Параметры, которых нет в реестре, игнорируются.
- Модуль без three и DOM, поэтому его грузит и `tools.html` без importmap, и jsc. В jsc нет `URLSearchParams`,
  для теста нужна подмена.

### `main.js`, `ui/touch.js`
- `const P = readParams()` вместо `URLSearchParams`. Проверки `params.has(x)` → `'x' in P`, флаги → `!!P.x`.
- `reefs` → `Math.trunc(P.reefs)`, как раньше `parseInt`. `twa` и `campitch` по умолчанию через `||`, как раньше
  (`?twa=` с пустым значением по-прежнему даёт 60).
- `isTouchDevice()` → `readParams().touch`.

### `tools.html` в корне
- **Стенды** — карточки карты мира, библиотеки объектов, лодки и моряка: что это, когда пригодится, 3–5
  готовых ссылок, полный список параметров (по шапкам и коду стендов).
- **Игра с параметрами** — 8 готовых сцен (perf, touch, перемотка `t`, вечер, свежий ветер, архипелаг только для
  просмотра) и таблица всех параметров, построенная из `GAME_PARAMS`. Пример в таблице — ссылка на игру.
- **Консоль** — `__sim` и что в нём, `polar()`, `runCase()`, `__props` / `__sailor` на стендах.
- **Командная строка** — сервер, jsc для `run-polar.mjs` и `trace.mjs`.
- Токены цвета скопированы из `style.css`: сам файл не подключён, потому что у `html, body` там `overflow: hidden`
  под канвас. На ширине ≤ 600 px сетка карточек становится одной колонкой, а строки таблицы раскладываются
  в столбик: имя и значения, пример, описание.

### Мелочи

- `README.md` — раздел «Инструменты» (ссылка на страницу и правило про реестр), строки `tools.html` и

## Решения
- Ссылки на страницу из самой игры нет — по ответу пользователя.
- Реестр только для параметров игры. Стенды разбирают свои параметры сами (у каждого своя логика, всё в одном
  файле), их параметры на карточках ведутся вручную.
- Пример для `pos` — `160,-90,180` (старт из `start.json`), чтобы лодка гарантированно оказалась в воде.

## Проверка
- jsc: `readParams('?wind=9&perf&pos=1,2,90&cam=chase&foo=1&clouds=Ясно')` →
  `{"pos":[1,2,90],"wind":9,"cam":"chase","clouds":"Ясно","perf":true}`, у всех 21 записи группа из `PARAM_GROUPS`.
- A/B против main (worktree HEAD на отдельном порту) с
  `?t=30&twa=60&wind=9&winddir=30&cam=chase&camaz=120&campolar=1.3&camdist=25&campitch=10&reefs=1&board=0&tod=0.9&clouds=Ясно&pos=160,-90,180&veg=0.5&dpr=1.25&perf=1&touch=1&log=1`:
  строка лога после перемотки совпала до цифры — `[sim] t=30.1 boat=(109.3,0.14,-89.5) u=2.35 heel=-9.0 cam=(125.6,8.0,-71.5) tws=8.4`,
  растительность 6966 экз. в обоих случаях. Совпали также ветер, режим и параметры камеры, рифы, шверт, dpr.
  Счётчик кадра и тач-управление видны.
- Все 29 ссылок со страницы открыты в headless Chrome: ошибок в консоли нет. Что проверка ловит ошибки, подтверждено
  на заведомо битой странице.
- Скриншоты: [1280 px](img/tools-1280.jpeg), [390 px](img/tools-390.jpeg). Горизонтальной прокрутки нет на
  обеих ширинах.

## Ограничения
- Карточки стендов ведутся вручную и могут устаревать.
- Значения `clouds` и `cam` в реестре записаны строкой, а не взяты из `CLOUD_TYPES` / `MODES`, чтобы не тянуть
  в реестр three.
